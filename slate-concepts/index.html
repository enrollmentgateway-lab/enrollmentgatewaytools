02

The record

Person fields or application fields?

A field is simply a stored fact. The important part is knowing what the fact describes—and therefore which record can have it.

One per individual

Person fields

Facts about the individual across their relationship with Gateway.

  • Preferred name
  • Email
  • Mobile phone
  • Mailing address
  • Person status
  • SIS ID
  • Teaching site

One set per application

Application fields

Facts about a particular attempt to enter a program and term.

  • Entry term
  • Degree program
  • Application status
  • Decision code
  • Decision date
!

Counting application rows does not automatically count unique people. One person may contribute more than one application to the result.

Once an application is decided

Decision codes tell you the outcome

Decided is an application status. It does not tell you which decision was made.

The applicant is admitted to this program and entry term. The application status moves to Decided.

The applicant is admitted with a condition still to satisfy—for example, a final transcript or a missing prerequisite—before enrollment is confirmed.

The application will not be admitted for the requested program and entry term. The same person may still apply to a different program or a later term.

Never place a decision code on the person. A person can receive different decisions on different applications.

The message

Content blocks or merge fields?

Both help make communications reusable, but at very different scales: one inserts prepared content; the other inserts one record value.

The request

Ask a question Slate can answer

A strong request does not prescribe how to build in Slate. It makes the decision, unit, scope, and desired output unmistakable.

78 + 17 + 10 = 105 decided applications

Decision codes describe only the 105 decided applications—not all 254 applications and not necessarily 105 unique people.

1

Read the title and “as of” date

This report covers Fall 2027 M.Div. applications in the current recruitment cycle, frozen at a point in time.

2

Name the unit

The unit is application records. “254” must not be relabeled “254 people” without a unique-person count.

3

Confirm the universe and exclusions

Only the named program, cycle, and shown sites are represented. The footnote says zero-count sites are hidden.

4

Understand the groups

The application-status columns are mutually exclusive here, so their totals add to 254. “Decided” still needs a decision-code breakdown.

5

Check the denominator before using a rate

For example, 105 ÷ 254 = 41.3% of shown applications decided. It is not an admit rate.

Interpretation practice

What can you safely conclude?

No. The report shows 105 applications with a Decided status. The decision-code view shows that some were provisional admits or denials, and the report does not establish a unique-person count.
No. Online has the largest raw application total. Conversion requires a defined starting population and denominator for every site.
Yes—with the report’s scope attached. As of September 1, 2026, 43 shown Fall 2027 M.Div. application records were in Awaiting Materials across the sites included here.
08

The checkpoint

Check your Slate thinking

Six quick scenarios. Choose the strongest answer, then review the reasoning.

1You want to compare application volume by teaching site. What output do you need?

A comparison of volume asks “how many?” and therefore needs a report.

2Where does “Awaiting Materials” belong?

It describes the state of a specific application. Another application for the same person can have a different status.

3A graduate requests information about a new degree. What is their person status?

Person status represents the furthest lifetime stage reached and does not reverse.

4What is the better starting lens for a current-interest email?

A population can express current relevance; person status alone may reflect only an old milestone.

5You want “Hello, Jordan” to use each recipient’s preferred name. What is Jordan?

A merge field inserts one stored record value. A content block inserts a reusable section.

6A report shows 254 application rows. How many unique people are represented?

One person can have multiple applications, so a unique-person count must be explicitly requested.

Keep this nearby

Slate in plain language

A quick reference for meetings, requests, and report reviews.

Query

Returns who or which records meet criteria. Think list, review, or action.

Report

Returns how many, often grouped or compared. Think count, aggregate, percentage, or trend.

Person field

A stored fact about the individual, such as contact information, SIS ID, or person status.

Application field

A stored fact about one application, such as program, entry term, application status, or decision.

Person status

The furthest stage a person has reached: Inquiries, Prospect, App, Student, or Graduate. It does not reverse.

Application status

The current state of one application: Awaiting Submission, Payment, Materials, or Decided.

Decision code

The outcome on a decided application: Admit, Admit Provisional, or Deny. It does not belong to a person.

Population

A bucket of records defined by a query filter—on fields like teaching site, term, or application year—rather than a fixed list. Usually the better lens for communication audiences than person status.

Campaign

The message sent to the records inside a population. A population defines who; a campaign defines what gets sent.

Pipeline

The recruiting stream, pathway, or initiative connecting people to a particular effort.

Teaching site

The local or online context associated with a person’s interest or application.

Content block

A reusable piece of communication, such as a program section, event details, or signature.

Merge field

A placeholder that inserts one value from a person, application, or related record.
